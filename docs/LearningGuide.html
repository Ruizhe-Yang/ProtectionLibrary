01

学习目标与阅读路线Learning objectives and reading route

ProtectionLibrary 用可组合元件表达保护链的不同职责：判据识别危险，表决处理多通道信息，协调逻辑决定命令权限，物理措施改变本体网络，独立反馈判断动作是否真正发生。它不是一个接上就能证明系统安全的黑箱。ProtectionLibrary separates the responsibilities of a protection chain: criteria identify conditions, voting handles channels, coordination selects authority, physical measures alter the plant, and independent feedback checks whether an action occurred. It is not a black box that proves a system safe merely by being connected.

本指南先讲清各层的接口与语义，再用九个案例学习迟滞、持续时间、锁存复位、表决资格、电气泄能、机械制动、热冷却和流体隔离。所有示例只需本库及 MSL 4.0.0。This guide explains layer interfaces and semantics before using nine examples to study hysteresis, persistence, latching and reset, qualified voting, electrical energy dissipation, braking, cooling and fluid isolation. The examples require only this library and MSL 4.0.0.

本指南依据固定提交的源码编写。示例中的数值与曲线描述为源码推导的复现参考，未在本次文档工作中重新运行 Modelica 仿真。This guide documents a fixed source revision. Numerical and curve descriptions are source-derived reproduction references; Modelica simulations were not re-run during this documentation work.

02

理解元件之前，先理解这些概念Concepts to understand before using the components

保护链中的每一层都要可观察Observe every layer of the protection chain

建议至少保留原始测量、判据请求、表决结果、所选命令、执行状态和本体响应。request=true 只能说明逻辑发出请求，不能说明电源已断开、转子已停止或温度已安全。Preserve raw measurement, criterion request, vote, selected command, actuator state and plant response. request=true means a request was issued, not that power was disconnected, a rotor stopped or temperature became safe.

迟滞与持续确认解决不同问题Hysteresis and persistence solve different problems

HighLimit 的 tripLevel 与 resetLevel 定义进入和退出判据的边界；Persistence 的 holdTime 要求一次连续成立。迟滞防止边界附近反复切换，驻留防止过短事件立即触发；不能把两者理解成同一个延时。HighLimit uses tripLevel and resetLevel for separate entry and exit boundaries. Persistence requires an uninterrupted holdTime. Hysteresis suppresses threshold chatter, while dwell rejects short events; they are not the same delay.

安全复位不是危险消失就自动解除Safe reset is not automatic release

TripLatch 保留请求，直到获得允许的 reset 上升沿；同时存在 trip 与 reset 时跳闸优先。ResetPermission 可以要求危险消失并持续安全一段时间。把 reset 永久置真不等同于每次都提供新的复位沿。TripLatch retains a request until a permitted rising reset edge is accepted; trip has priority over a simultaneous reset. ResetPermission can require continuous safe dwell. A permanently true reset is not a fresh reset edge on every occasion.

有效通道数与表决结果是两个输出Valid-channel count and vote are separate outputs

布尔表决按 invalidVote 处理无效通道；enoughValid 是诊断输出，不会自动关闭 y。模拟量融合的 fallbackValue 可能是可绘制的实数，但 available=false 时不能把它当成有效测量。Boolean voters use invalidVote for unqualified channels. enoughValid is diagnostic and does not automatically suppress y. Analogue fallbackValue remains a plottable number, but it is not a qualified measurement when available=false.

动作确认需要独立反馈Action confirmation requires independent feedback

ActionMonitor 的 measuredAction 应来自实际执行器状态或另建的测量路径。把 command 原样接回 measuredAction 会把命令当成成功证据，掩盖延迟与拒动。状态输出仍是模型内部的行为，不等于真实传感器已经验证。Feed ActionMonitor.measuredAction from an actuator state or a separately modelled measurement path. Feeding command straight back would mistake a request for success and conceal delay or refusal. A model state is still not independently validated physical sensing.

因果信号端口用于传递数值或逻辑；电气、机械、热和流体物理端口参与网络方程。不能把物理端口当作普通输入输出，也不能用一个布尔保护请求代替实际的能量或物质通路。Causal signal connectors convey values or logic. Electrical, mechanical, thermal and fluid connectors participate in network equations. A physical connector is not an ordinary signal input, and a Boolean request does not replace an energy or material path.

within ProtectionLibrary.Coordination;
block ActionMonitor "Compare each command with measured action before deciding timeout"
parameter Modelica.Units.SI.Time timeout(min=0)=0.2;
    Modelica.Blocks.Interfaces.BooleanInput command ;
  Modelica.Blocks.Interfaces.BooleanInput measuredAction ;
  Modelica.Blocks.Interfaces.BooleanOutput acknowledged(start=false,fixed=true) ;
  Modelica.Blocks.Interfaces.BooleanOutput failed(start=false,fixed=true) ;
  Modelica.Blocks.Interfaces.BooleanOutput late(start=false,fixed=true) ;
  Modelica.Blocks.Interfaces.BooleanOutput unexpectedAction(start=false,fixed=true) ;
  Modelica.Blocks.Interfaces.RealOutput requestTime(unit="s",start=0,fixed=true) ;
  Modelica.Blocks.Interfaces.RealOutput actionTime(unit="s",start=0,fixed=true) ;
  output Integer failureCount(start=0,fixed=true);
protected
  discrete Boolean observed(start=false,fixed=true);
  Boolean due;
  discrete Modelica.Units.SI.Time recordedTime(start=0,fixed=true);
initial equation
  assert(timeout>=0,"Negative action timeout.");
equation
  when {initial(),command} then requestTime=if command then time else 0; end when;
  due=command and time>=requestTime+timeout;
  actionTime=if observed then recordedTime else 0;
algorithm
  when {initial(),command,not command,measuredAction,due} then
    if not command then
      unexpectedAction:=pre(unexpectedAction) or measuredAction;
    elseif initial() or time<=requestTime then
      observed:=measuredAction;
      recordedTime:=if measuredAction then time else 0;
      acknowledged:=measuredAction;
      failed:=not measuredAction and timeout<=0;
      late:=false;
      failureCount:=pre(failureCount)+(if failed then 1 else 0);
    else
      observed:=pre(observed) or measuredAction;
      if measuredAction and not pre(observed) then
        recordedTime:=time;
        acknowledged:=not pre(failed) and time<=requestTime+timeout+1e-8;
        late:=not acknowledged;
      end if;
      failed:=pre(failed) or ((due or late) and not acknowledged);
      failureCount:=pre(failureCount)+(if failed and not pre(failed) then 1 else 0);
    end if;
  end when;
end ActionMonitor;

研究问题Question

短时越限与持续危险如何形成锁存保护？How do short and sustained conditions produce a latched trip?

如何实现How it is assembled

signal 在 12 与 7 间切换。HighLimit 使用 10/8 的进入与复位门限，Persistence 驻留 0.2 s，ResetPermission 安全等待 0.25 s；复位脉冲在 1.2 和 3.4 s。signal switches between 12 and 7. 应当观察到什么What to look for

排错、适用边界与常见误读Troubleshooting, scope and common misinterpretations

所有通道无效时为何表决为真Why is the vote true with no valid channels?

先看 invalidVote。默认把无效通道当作请求，可能是一种失效安全策略；enoughValid 不会自动抑制 y。必须在系统层说明这种策略的预期后果。Inspect invalidVote. Counting invalid channels as requests can be an intentional fail-safe policy; enoughValid does not inhibit y automatically. Explain the resulting system-level behaviour.

复位为什么无效Why was reset rejected?

检查 trip 是否仍为真、resetAllowed 是否为真，以及 reset 是否确实出现新的上升沿。只把测量值降回门限附近可能尚未满足迟滞和连续安全驻留。Check whether trip remains true, resetAllowed is true and a new rising reset edge occurred. Returning a measurement near its threshold may not satisfy hysteresis or continuous safe dwell.

已断开但仍有残余电流或流量Why does flow remain after isolation?

物理元件保留有限 Goff、泄漏或残余导通，模型可能有储能。把残余量和参数对应起来，不要简单把非零输出判为实现错误。Finite off-conductance, leakage, residual transmission and stored energy can remain. Relate the residual to the declared parameters rather than treating every non-zero value as an implementation error.

保护成功能否等价于系统安全Does successful protection prove safety?

不能。应同时检查保护动作、残余响应、其他安全目标以及保护造成的副作用。示例不构成认证，也不提供概率可靠性结论。No. Inspect the action, residual response, other safety objectives and adverse effects of protection. The examples are not certification or probabilistic reliability evidence.

报错时先定位最小问题：加载失败、模型不平衡、初始化冲突、积分失败、输出不符合预期，是不同层次的问题。提交 issue 时给出最小模型、参数、工具版本、完整诊断和预期结果。不要用放宽容差掩盖接线或物理定义错误。Separate loading failures, structural imbalance, initialisation conflicts, integration failures and unexpected outputs. An issue should include a minimal model, parameters, tool version, complete diagnostics and expected behaviour. Do not use looser tolerances to conceal topology or physical-definition errors.

within ProtectionLibrary.Utilities.Functions;
function Fuse "Evaluate one finite analog fusion from qualified inputs"
  extends Modelica.Icons.Function;
input Real u[:];
  input Boolean valid[size(u,1)];
  input Real weights[size(u,1)];
  input Integer minValid;
  input Integer trimEachSide;
  input ProtectionLibrary.Utilities.Types.AnalogMethod method;
  output Real value;
  output Integer nValid;
  output Boolean available;
protected
  Real ordered[size(u,1)];
  Real sumValue;
  Real weightTotal;
  Real weighted;
  Real selected;
  Integer k;
algorithm
  nValid:=0; ordered:=fill(0,size(u,1));
  sumValue:=0; weightTotal:=0; weighted:=0;
  for i in 1:size(u,1) loop
    if valid[i] and abs(u[i])<Modelica.Constants.inf then
      nValid:=nValid+1;
      ordered[nValid]:=u[i];
      sumValue:=sumValue+u[i];
      weightTotal:=weightTotal+weights[i];
      weighted:=weighted+weights[i]*u[i];
    end if;
  end for;
  available:=nValid>=minValid;
  value:=0;
  if available then
    if method==ProtectionLibrary.Utilities.Types.AnalogMethod.Mean then value:=sumValue/nValid;
    elseif method==ProtectionLibrary.Utilities.Types.AnalogMethod.WeightedMean then
      available:=weightTotal>0;
      if available then value:=weighted/weightTotal; end if;
    else
      for i in 2:nValid loop
        selected:=ordered[i]; k:=i-1;
        while k>0 loop
          if ordered[k]<=selected then break; end if;
          ordered[k+1]:=ordered[k]; k:=k-1;
        end while;
        ordered[k+1]:=selected;
      end for;
      if method==ProtectionLibrary.Utilities.Types.AnalogMethod.Median then
        value:=if mod(nValid,2)==0 then 0.5*(ordered[div(nValid,2)]+ordered[div(nValid,2)+1]) else ordered[div(nValid,2)+1];
      else
        available:=nValid-2*trimEachSide>=minValid;
        if available then value:=sum(ordered[j] for j in trimEachSide+1:nValid-trimEachSide)/(nValid-2*trimEachSide); end if;
      end if;
    end if;
  end if;
end Fuse;

function fusedValue "对同单位向量计算中位数、均值、截尾或加权均值"
  input Real x[:];
  input ProtectionLibrary.Utilities.Types.FusionMethod method;
  input Integer trimEachSide;
  input Real weights[size(x,1)];
  output Real y;
protected
  Integer n = size(x,1);
  Integer middle;
  Real sorted[size(x,1)];
algorithm
  if method == ProtectionLibrary.Utilities.Types.FusionMethod.Mean then
    y := sum(x)/n;
  elseif method == ProtectionLibrary.Utilities.Types.FusionMethod.Weighted then
    y := sum({x[i]*(weights[i]/sum(weights)) for i in 1:n});
  else
    sorted := Modelica.Math.Vectors.sort(x);
    if method == ProtectionLibrary.Utilities.Types.FusionMethod.Trimmed then
      y := sum(sorted[1+trimEachSide:n-trimEachSide])/(n-2*trimEachSide);
    else
      middle := div(n+1,2);
      y := (sorted[middle]+sorted[n+1-middle])/2;
    end if;
  end if;
end fusedValue;
